# نسخه اندروید سینما ۵۰۰

این پروژه در مسیر `android/` یک اپلیکیشن اندروید بومیِ سبک دارد که وب‌سایت رسمی
`https://riphatake16-debug.github.io/cinema500/` را در WebView امن باز می‌کند.
نسخه وب/PWA و گردش‌کار انتشار GitHub Pages بدون تغییر باقی می‌مانند.

## ویژگی‌ها و محدودیت‌ها

- نام برنامه: **سینما ۵۰۰**؛ آیکون از `icons/icon-192.png` ساخته می‌شود.
- شناسه ثابت برنامه: `ir.cinema500.app` (پس از اولین انتشار عوض نکنید).
- نمایش بدون نوار مرورگر و تمام‌صفحه، با دکمه بازگشت، صفحه تلاش مجدد زمان قطع اینترنت.
- ذخیره دفتر تماشا در فضای اختصاصی WebView و پشتیبانی از ورود/خروج فایل JSON.
- فقط صفحات `https://riphatake16-debug.github.io/cinema500/` در اپ باز می‌شوند؛
  لینک‌های خارجی HTTPS به مرورگر یا برنامه مناسب فرستاده می‌شوند.
- پل فایل پشتیبان فقط از صفحه اصلی دامنه تأییدشده پیام می‌پذیرد، نه از iframe یا سایت بیرونی.
- دسترسی اینترنت الزامی است. اپ فعلاً نسخه آفلاین از کل سایت ندارد.
- داده‌های ذخیره‌شده در Chrome/PWA به WebView **منتقل نمی‌شوند**: ابتدا از سایت
  «دریافت پشتیبان» بگیرید، سپس فایل JSON را در اپ جدید «بازیابی» کنید.
- نصب هم‌زمان APK آزمایشی (debug) و نسخه انتشار یکسان ممکن نیست؛ قبل از نصب
  نسخه نهایی، از داده‌های آزمایشی پشتیبان بگیرید و APK debug را حذف کنید.
- نمایش محتوای وب به‌تنهایی تضمین پذیرش مارکت نیست؛ موارد قوانین/حقوق محتوا و
  الزامات حریم خصوصی و کیفیت را در مایکت و بازار بررسی کنید.

## گرفتن APK آزمایشی از GitHub

1. تغییرات این شاخه را با Pull Request به `main` ادغام کنید.
2. از تب **Actions**، گردش‌کار **Build Android APK** را اجرا کنید
   (یا پس از ادغام تغییرات `android/` منتظر اجرای خودکار باشید).
3. در اجرای موفق، از قسمت **Artifacts** فایل `cinema500-debug-apk` را بگیرید
   و فایل `app-debug.apk` داخل آن را برای تست روی گوشی نصب کنید.
   این فایل برای انتشار در مارکت مناسب نیست.

از Android Studio یا خط فرمان هم می‌توان ساخت:

```bash
gradle -p android :app:assembleDebug
```

ابزارهای لازم: JDK 17، Android SDK 35، Gradle 8.10.2. این مخزن
Gradle Wrapper باینری ندارد و گردش‌کار GitHub خودش Gradle را تهیه می‌کند.

## امضای APK انتشار

برای انتشار باید **کلید امضای دائمی خودتان** را یک بار، در رایانه شخصی،
ایجاد و در جایی امن پشتیبان‌گیری کنید؛ فایل کلید و گذرواژه را هرگز در مخزن
یا پیام عمومی قرار ندهید. نمونه:

```bash
keytool -genkeypair -v -keystore cinema500-release.jks -alias cinema500 \
  -keyalg RSA -keysize 3072 -validity 10000
```

در **Settings → Secrets and variables → Actions** مخزن، این چهار Secret را ثبت کنید:

| Secret | مقدار |
| --- | --- |
| `CINEMA500_KEYSTORE_BASE64` | متن Base64 فایل keystore (در لینوکس: `base64 -w0 cinema500-release.jks`) |
| `CINEMA500_KEYSTORE_PASSWORD` | رمز keystore |
| `CINEMA500_KEY_ALIAS` | نام alias (مثلاً `cinema500`) |
| `CINEMA500_KEY_PASSWORD` | رمز کلید |

سپس از تب **Actions → Build Android APK → Run workflow** اجرای دستی انجام دهید.
اگر چهار Secret تنظیم شده باشند، در کنار APK آزمایشی، Artifact
`cinema500-market-release-apk` با فایل `app-release.apk` ساخته می‌شود.
در نبود Secret، **فقط APK آزمایشی** تولید می‌شود و هیچ فایل امضانشده‌ای
به عنوان نسخه قابل انتشار معرفی نمی‌شود.

برای انتشار در نسخه‌های بعد، شماره `versionCode` را در
`android/app/build.gradle` افزایش دهید و **همان keystore قبلی** را نگه دارید.
پیشنهاد می‌شود از یک امضای ثابت برای هر دو مارکت استفاده کنید تا مسیر
به‌روزرسانی دچار مشکل نشود.

## چک‌لیست آزمون قبل از انتشار

1. اجرا، جست‌وجوی فارسی، فیلترها، گردونه، جزئیات آثار، تم روشن/تاریک.
2. ثبت یک فیلم دیده‌شده، نمره و یادداشت؛ بستن و بازکردن اپ و حفظ داده.
3. «دریافت پشتیبان» و ذخیره `cinema500-journal.json` در Android Documents.
4. «بازیابی پشتیبان» با انتخاب همان فایل، تأیید ادغام و بازگشت داده.
5. بازکردن لینک IMDb یا منابع بیرونی در مرورگر دستگاه.
6. حالت قطع اینترنت، پیام خطا و دکمه تلاش دوباره بعد از اتصال.
7. دکمه Back در جزئیات، فیلترها و صفحه اصلی، همچنین صفحه‌کلید نرم‌افزاری.
8. تست روی چند نسخه اندروید؛ تست روی دستگاه واقعی پیش از ارسال.
9. بررسی تصاویر، نام‌ها، شرح، اسکرین‌شات‌ها، سیاست حریم خصوصی و حقوق محتوا
   مطابق دستورالعمل‌های جاری هر مارکت.

## چرا از TWA استفاده نشده؟

آدرس سایت در مسیر پروژه GitHub Pages (`/cinema500/`) است. TWA برای حذف نوار
مرورگر به `https://riphatake16-debug.github.io/.well-known/assetlinks.json`
در **ریشه دامنه** نیاز دارد؛ قراردادن این فایل زیر `/cinema500/` کافی نیست.
WebView محدودشده به دامنه خود سایت فعلاً بدون نیاز به ایجاد سایت ریشه یا
خرید دامنه، امکان ساخت APK را فراهم می‌کند. اگر بعدها دامنه اختصاصی
تأییدشده فراهم شد، می‌توان به TWA مهاجرت کرد.
